# Security Policy

## Supported Versions

Security fixes are shipped on the latest public release of CheckMyCode. If you are using an older build, update to the latest release before reporting an issue unless the issue still reproduces there.

## Reporting Vulnerabilities

Please do not open a public issue for a vulnerability in CheckMyCode or its scan engine.

Report it privately through GitHub: open the repository's **Security** tab and choose **Report a vulnerability** (GitHub private vulnerability reporting).

Include:

- affected version or commit
- operating system and architecture
- clear reproduction steps
- expected and actual behavior
- logs, screenshots, or proof of concept details when safe to share

We aim to acknowledge reports within 72 hours and will coordinate a fix and disclosure timeline based on impact.

## Scanner Findings

If CheckMyCode reports a false positive in your project, public issues are fine as long as the report does not disclose secrets, private source code, customer data, or exploitable details from a private system.

## Supply Chain

Release artifacts should be verified against published checksums when available. Do not install desktop builds from unofficial mirrors.
